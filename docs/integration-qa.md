## Реальный браузер + HTTP + SQLite

Запущен отдельный `server.main.make_server` на свободном loopback-порту с временной SQLite-базой. Параметры провайдера явно пустые: тест не расходовал AI-кредиты и не обращался к внешней модели. Рабочая база пользователя не использовалась.

Пройдены:

1. Загрузка синтетического каталога и честная индикация режима.
2. Начало диалога из демо-черновика и ответ на вопрос реального локального AI-модуля.
3. Отсутствие автоматического изменения полей: применение факта только кнопкой; отмена и повторное применение.
4. Ручное заполнение полной карточки, рейтинг 100/100.
5. Подтверждение публикации и просмотр всех полей в «Подробнее».
6. Отправка отклика через API, ручной выбор команды, начисление 100 points.
7. Восстановление задачи, отклика и выбора после перезагрузки.
8. Отдельный браузерный контекст видит эти же данные из SQLite без общего localStorage.
9. «Новая задача» очищает черновик и не удаляет опубликованные данные.
10. Задержанный AI-ответ после ручной правки отклоняется как устаревший; новая правка сохраняется, повтор запроса работает.
11. Искусственный HTTP 503 показывает точное сообщение API, сохраняет введённый текст и позволяет повторить запрос.
12. Ещё 12 ходов реального диалога: 30 сообщений на экране, лимиты API не нарушены.
13. Ширины 320, 390, 820, 1440 px: ширина документа совпадает с viewport. Мобильные вкладки переключаются и показывают нужные поля.
14. Минимальная карточка с рейтингом 35 публикуется; фильтр «Готовая+» её скрывает. Повторная публикация обновляет существующую задачу без дубля.
15. В отдельном браузерном контексте искусственно недоступный health-check включает явно обозначенное статическое демо: 5 откликов и корректная привязка ответа к вопросу о пользователях.

В основном сквозном сценарии ошибок JavaScript не было. В негативной проверке браузер зарегистрировал ожидаемый HTTP 503 от искусственно прерванного запроса; ошибка была обработана интерфейсом.

Финальная повторная проверка после изменений трёх чатов: на новой временной базе снова пройдены диалог с реальным локальным AI-модулем, ручное применение факта, карточка 100/100, публикация, подробности, отклик, выбор команды, 100 points и сохранение после перезагрузки. В отклике использована ссылка с 900 последовательными символами в пути: на ширинах 320, 390, 820 и 1440 px нет переполнения ни страницы, ни карточки отклика. Ошибок JavaScript в этом прогоне нет. Проверенный рабочий сервер 4174 оставлен запущенным; тестовые записи создавались только во временной базе отдельного сервера.

## Исправлено при интеграции

- Чтение `error.message` / `error.code` из серверного конверта и таймауты запросов.
- Метка подключённой LLM больше не появляется только из-за успешного health-check.
- Ограниченное окно истории согласовано с HTTP-контрактом.
- Ручная правка после применения факта не затирается его отменой; новая правка во время публикации также сохраняется.
- Повторный клик не создаёт второй запрос публикации или отклика.
- Новый черновик в API-режиме вместо ссылки на несуществующую серверную панель.
- Демо-адаптер корректно привязывает первый ответ к заданному вопросу и восстанавливается при повреждённых записях localStorage.
- README и сценарий демо обновлены под серверную версию на порту 4174.

## Не подтверждено / ограничения

- Живой ответ внешней LLM не тестировался; наличие адаптера не означает подключённую модель.

- Неопубликованный черновик и чат не сохраняются после перезагрузки.

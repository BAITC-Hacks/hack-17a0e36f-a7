## Финальная браузерная проверка после сверки с кейсом

Отдельный сервер на свободном loopback-порту, временная SQLite-база, явно отключённый внешний AI. Playwright в настоящем браузере подтвердил:

1. Слабый черновик вызывает разные вопросы об артефакте, критерии успеха и данных; следующий вопрос — о пользователях. Режим честно указан как «Локальный помощник».
2. Три ответа применяются вручную по одному; рейтинг меняется 15 → 30 → 50. После заполнения остальных полей — 100/100; публикация появляется в каталоге.
3. Две разные команды оставляют отклики на одну задачу, бизнес выбирает обе. Сам выбор оставляет у всех 0 points.
4. Пустое описание выполненного этапа не начисляет баллы. Подтверждённый этап с описанием даёт первой команде 100 points, у второй остаётся 0.
5. После перезагрузки сохранены задача, обе выбранные команды, описание выполненного этапа и 100 points. Повторное начисление дополнительно проверено конкурентными API-тестами.
6. Ссылка на прототип с 900 символами в пути, расширенные профили команд и элементы подтверждения этапа не создают горизонтального переполнения на 320, 390, 820 и 1440 px.
7. В сквозном сценарии ошибок JavaScript не зарегистрировано. Один первоначальный шаг QA ожидал несуществующую метку «Резервный режим» и завершился таймаутом тестового локатора; после сверки с реальной меткой «Локальный помощник» сценарий пройден успешно. Ошибки приложения это ожидание не выявило.

Рабочий сервер 4174 безопасно перезапущен с новой версией. Перед миграцией создана SQLite-копия `server/data/pre-case-alignment-20260923-1729.sqlite3`, не включаемая в Git. После миграции: 5 задач, 5 команд, 5 ожидающих откликов, 0 подтверждённых этапов; `PRAGMA integrity_check` — `ok`. Сравнение с резервной копией: 0 изменённых строк задач и 0 изменённых исходных полей откликов. Рабочая база не сбрасывалась и не заполнялась тестовыми записями. Health: `{"status":"ok","storage":"sqlite","aiConfigured":false}`.

## Предыдущий интеграционный прогон — до финальной сверки кейса

Запущен отдельный `server.main.make_server` на свободном loopback-порту с временной SQLite-базой. Параметры провайдера явно пустые: тест не расходовал AI-кредиты и не обращался к внешней модели. Рабочая база пользователя не использовалась.

Пройдены:

1. Загрузка синтетического каталога и честная индикация режима.
2. Начало диалога из демо-черновика и ответ на вопрос реального локального AI-модуля.
3. Отсутствие автоматического изменения полей: применение факта только кнопкой; отмена и повторное применение.
4. Ручное заполнение полной карточки, рейтинг 100/100.
5. Подтверждение публикации и просмотр всех полей в «Подробнее».
6. Отправка отклика через API и ручной выбор команды. Прежнее начисление баллов за выбор заменено отдельным подтверждением этапа; актуальная проверка описана выше.
7. Восстановление задачи, отклика и выбора после перезагрузки.
8. Отдельный браузерный контекст видит эти же данные из SQLite без общего localStorage.
9. «Новая задача» очищает черновик и не удаляет опубликованные данные.
10. Задержанный AI-ответ после ручной правки отклоняется как устаревший; новая правка сохраняется, повтор запроса работает.
11. Искусственный HTTP 503 показывает точное сообщение API, сохраняет введённый текст и позволяет повторить запрос.
12. Ещё 12 ходов реального диалога: 30 сообщений на экране, лимиты API не нарушены.
13. Ширины 320, 390, 820, 1440 px: ширина документа совпадает с viewport. Мобильные вкладки переключаются и показывают нужные поля.
14. Минимальная карточка с рейтингом 35 публикуется; фильтр «Готовая+» её скрывает. Повторная публикация обновляет существующую задачу без дубля.
15. В отдельном браузерном контексте искусственно недоступный health-check включает явно обозначенное статическое демо: 5 откликов и корректная привязка ответа к вопросу о пользователях.

В основном сквозном сценарии ошибок JavaScript не было. В негативной проверке браузер зарегистрировал ожидаемый HTTP 503 от искусственно прерванного запроса; ошибка была обработана интерфейсом.

Предыдущая повторная проверка после изменений трёх чатов также подтвердила диалог, ручное применение факта, карточку 100/100, публикацию, подробности и сохранение после перезагрузки. Правило начисления баллов впоследствии исправлено по официальному кейсу и повторно проверено в финальном сценарии выше.

## Исправлено при интеграции

- Чтение `error.message` / `error.code` из серверного конверта и таймауты запросов.
- Метка подключённой LLM больше не появляется только из-за успешного health-check.
- Ограниченное окно истории согласовано с HTTP-контрактом.
- Ручная правка после применения факта не затирается его отменой; новая правка во время публикации также сохраняется.
- Повторный клик не создаёт второй запрос публикации или отклика.
- Новый черновик в API-режиме вместо ссылки на несуществующую серверную панель.
- Демо-адаптер корректно привязывает первый ответ к заданному вопросу и восстанавливается при повреждённых записях localStorage.
- README и сценарий демо обновлены под серверную версию на порту 4174.
- По кейсу разрешён выбор нескольких команд; баллы выдаются только за подтверждённый выполненный этап. Добавлены недостающие профили и 5 черновиков разной полноты.
- Подготовлены `SUBMISSION.md` и `docs/requirements-checklist.md`: что подавать, ограничения MVP и организационные вопросы, которые код не подтверждает.

## Не подтверждено / ограничения

- Живой ответ внешней LLM не тестировался; наличие адаптера не означает подключённую модель.
- Раздел 5 официального кейса допускает fallback при недоступности API с демонстрацией промпта, формата и обработки ошибок; соответствующие материалы и проверки есть в репозитории.
- Форма «Сдать решение» автоматически не отправлялась. Допуск участницы без команды 3–5 человек нужно подтвердить отдельно у организаторов.
- Нет авторизации и проверки ролей. Сервер предназначен для локальной демонстрации.
- Неопубликованный черновик и чат не сохраняются после перезагрузки.
- Перечисленные проверки не являются полноценным аудитом безопасности или нагрузочным тестированием.

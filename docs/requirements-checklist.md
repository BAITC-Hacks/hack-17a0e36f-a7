# Сверка с официальным кейсом

Источник: предоставленные участницей PDF «HackAlem AI_ кейс по геймификации практических заданий», «Инструкция_для_участников_HackAlem_AI», «Правила зачета участия». Сверка выполнена 2026-09-23. Это техническая проверка, не решение жюри о зачёте.

| Требование | Реализация / проверка |
| --- | --- |
| Черновик и минимум 3 уместных вопроса | Диалог; отдельный AI-тест последовательности result → success → data → users; в DEMO предусмотрены 3 ответа. |
| Редактируемая карточка и ручное подтверждение | Все поля доступны; факты/предложения применяются отдельно; публикация с подтверждением. Контекст и потребность объединены в одно поле, как в шкале рейтинга. |
| Рейтинг 0–100, расшифровка, пересчёт | Веса 20/20/15/15/10/10/10; клиент и сервер; тесты уровней. Рейтинг отражает заполненность, не истинность сведений. |
| Общий каталог, сортировка и фильтры | Все опубликованные задачи; фильтры темы/готовности; низкий рейтинг не запрещает отклик. |
| Отклики и ручной выбор | Идея, план со сроком, ссылка; бизнес может выбрать несколько команд или отклонить предложения. Решение не принимает AI. |
| Баллы после подтверждённого этапа | Отдельное подтверждение с описанием результата; один этап на отклик в MVP; защита от повторных баллов. |
| AI и резервный режим | Адаптер внешней модели; проверенный fallback. Раздел 5 допускает его при недоступности API при наличии промпта, входа/выхода и обработки ошибок. Все три материала есть. |
| 5 черновиков | `data/demo-drafts.json`: отрасли и разная полнота. |
| 5 карточек, 5 команд, 5 откликов | Синтетический seed в `server/main.py`; профили содержат имя, интересы, навыки, технологии; срок указан в плане отклика. |
| Воспроизводимый запуск и README | Python 3.9+, стандартная библиотека, SQLite; инструкция, архитектура, сценарий, ограничения и тесты. |
| Демонстрация до 5 минут | `DEMO.md`: путь от слабого черновика до подтверждения этапа. |
| Репозиторий и подача | Выданный организаторами репозиторий; текст формы — `SUBMISSION.md`. Отправку формы участница выполняет отдельно. |

## Ограничения и непроверенные условия

- Живой LLM не проверен и не заявляется работающим. Это отдельно от допустимости fallback.
- Отсутствуют авторизация, облачное размещение и автоматическая проверка качества результата. Подтверждение этапа — ручное действие бизнеса, не независимый аудит работы команды.
- Набор команд демонстрационный; один отклик команды на задачу — упрощение MVP, повторные дубликаты блокируются.
- Допуск соло-участницы при указанном в PDF составе 3–5 человек требует решения организаторов; присутствие, сроки и зачёт не подтверждались программно.

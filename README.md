# SanaMatch

SanaMatch — MVP для кейса AI Sana Challenge Hub. Платформа помогает бизнесу превратить короткий черновик потребности в структурированную карточку задачи, оценить её готовность и опубликовать в каталоге. Студенческие команды выбирают интересные задачи, подают предложения, а бизнес вручную выбирает исполнителя.

## Проблема

Бизнес часто формулирует задачу слишком кратко: студентам не хватает контекста, данных, ограничений и понятных критериев успеха. Из-за этого подходящие команды не откликаются или начинают работу с длинных уточнений.

## Что реализовано

- Свободный ввод черновика бизнес-задачи.
- Локальный AI-чат-бот: анализирует заполненность, задаёт три уточняющих вопроса по одному и сохраняет ответы в черновик карточки.
- Редактируемая карточка с обязательными полями задачи.
- Прозрачный рейтинг готовности от 0 до 100 с расшифровкой баллов и подсказками.
- Открытый каталог задач: сортировка по рейтингу, фильтры по теме и уровню готовности.
- Демонстрационные данные: 5 задач, 5 профилей команд и 5 откликов.
- Отправка предложения командой и ручной выбор или отклонение отклика бизнесом.
- Одна команда может отправить только один отклик на задачу; для каждой задачи бизнес вручную выбирает не более одной команды.
- Progress points: выбранная вручную команда получает 100 баллов в таблице лидеров.
- Сохранение демонстрационных изменений в `localStorage` браузера.

## Главный сценарий

1. Представитель бизнеса вводит короткое описание задачи.
2. AI-чат-бот ведёт короткий диалог по отсутствующим сведениям и сохраняет ответы.
3. Бизнес дополняет и подтверждает редактируемую карточку.
4. Рейтинг автоматически пересчитывается и показывает, что нужно улучшить.
5. Задача публикуется в каталоге в позиции, соответствующей рейтингу.
6. Команда открывает задачу и отправляет идею, план и ссылку на прототип.
7. Бизнес вручную выбирает или отклоняет отклик. При выборе команда получает отметку о баллах прогресса.

## Формула рейтинга

| Показатель | Баллы |
| --- | ---: |
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт и формат взаимодействия | 10 |

Уровни: 0–39 — черновик, 40–69 — рабочая, 70–89 — готовая, 90–100 — приоритетная.

## AI-функция

В MVP работает локальный детерминированный анализатор правил; внешний LLM/API не вызывается. Анализатор ищет в черновике признаки упоминания семи полей карточки: данных, результата, критериев успеха, ограничений, пользователей, контакта и формата взаимодействия. Сначала задаёт вопросы по полям без найденных признаков, затем — вопросы на уточнение упомянутых полей, чтобы получить ровно три разных вопроса. Ключевое слово считается только сигналом для выбора вопроса, а не подтверждением полноты или истинности сведений.

Ответ на каждый вопрос привязан к его `field` и сохраняется только в соответствующее поле карточки. Бот не дополняет ответ и не переносит его в другие поля. После диалога карточку можно проверить и отредактировать вручную.

### Политика агента (prompt/spec)

```text
Ты помогаешь автору бизнес-задачи уточнить карточку SanaMatch.
Используй только текст черновика и существующие поля карточки.
Сначала спрашивай о полях, которые не упомянуты явно; затем задавай
нейтральные вопросы на уточнение, пока не будет ровно три разных вопроса.
Не придумывай факты, значения, сроки, метрики, пользователей или ответы.
Ключевое слово — лишь признак упоминания, а не подтверждение заполненности.
Сохраняй ответ пользователя только в поле, указанном у заданного вопроса.
При невозможности анализа используй безопасные общие вопросы и явно сообщи
о fallback. Верни структурированный JSON по описанному контракту.
```

Этот prompt/spec документирует поведение. Он не отправляется модели: в текущем MVP нет внешней модели.

### Контракт анализа

Вход функции `window.SanaMatchAI.analyze(input)`:

```json
{ "draft": "Интернет-магазин обрабатывает обращения клиентов вручную. Хотим сократить время обработки." }
```

Результат анализа:

```json
{
  "status": "ok",
  "mode": "local_rules",
  "missing_fields": ["data", "result", "success", "constraints", "contact", "format"],
  "mentioned_fields": ["users"],
  "questions": [
    { "field": "data", "text": "Есть ли примеры таких обращений или другие материалы, доступные команде?" },
    { "field": "result", "text": "На сколько нужно сократить время обработки и за какой период?" },
    { "field": "success", "text": "По какой метрике и какому целевому значению вы оцените это изменение?" }
  ]
}
```

`missing_fields` означает, что локальные правила не нашли сигналов упоминания; `mentioned_fields` означает только совпадение с ключевыми словами. Ни одно из этих полей не является проверкой фактов.

Ответ передаётся отдельно в `window.SanaMatchAI.applyAnswer(task, field, answer)`, например: `{ "field": "data", "answer": "..." }`. Успешный результат записи: `{ "status": "ok", "card_update": { "field": "data", "value": "..." } }`. Приложение принимает только известные поля и непустые текстовые ответы.

### Fallback и ошибки

- Пустой черновик не запускает анализ; пустой ответ не записывается, интерфейс просит повторить ввод.
- Если внутренняя логика анализа завершается ошибкой, возвращается `mode: "safe_fallback"` с тремя нейтральными вопросами. В fallback `missing_fields` и `mentioned_fields` пустые: анализатор не утверждает, что знает, какие поля пропущены.
- Сетевая/API ошибка невозможна в текущем сценарии: внешнего вызова нет. Данные черновика и ответов не отправляются модели.
- Вопросы и ответы отображаются как текст, а не как HTML.

## Архитектура

```text
index.html  →  интерфейс и пользовательские сценарии
app.js      →  локальный AI fallback, рейтинг, каталог, отклики, localStorage
styles.css  →  адаптивное визуальное оформление
```

MVP сделан как статическое веб-приложение, чтобы его можно было открыть и проверить без учётных записей, базы данных и внешних сервисов.

## Запуск

Нужен любой статический HTTP-сервер. В macOS/Linux:

```bash
python3 -m http.server 4173
```

Откройте [http://localhost:4173](http://localhost:4173) в браузере.

Также можно открыть `index.html` напрямую, но HTTP-сервер рекомендуется для одинакового поведения в браузерах.

## Как проверить

1. На главном экране вставьте короткий черновик: «Нам нужно быстрее обрабатывать обращения клиентов интернет-магазина».
2. Нажмите «Проанализировать черновик» и убедитесь, что появились минимум три вопроса.
3. Сформируйте карточку, заполните данные, результат, критерии успеха, ограничения, пользователей, контакт и формат работы.
4. Наблюдайте рост рейтинга и смену уровня готовности.
5. Опубликуйте задачу: она появится в каталоге.
6. Нажмите «Откликнуться», выберите команду, добавьте идею и план, отправьте предложение.
7. В разделе «Решение бизнеса» нажмите «Выбрать» или «Отклонить» у отклика.

## Данные и интеграции

Все данные синтетические и находятся в `app.js`. Внешние API, персональные данные и секреты не используются. Рейтинг и статусы выбранных команд сохраняются в `localStorage`; при повреждённом значении приложение безопасно возвращается к демонстрационным данным.

## Ограничения

- В текущем MVP нет регистрации и реальной ролевой модели.
- Данные хранятся только в `localStorage` конкретного браузера.
- AI-анализатор — локальный fallback, а не внешний LLM API.
- Нет продакшн-бэкенда, файлового хранилища, уведомлений и календаря.

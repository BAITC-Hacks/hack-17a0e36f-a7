# SanaMatch

MVP для кейса **AI Sana Challenge Hub**: бизнес превращает короткое описание в понятную задачу, студенческие команды откликаются, а бизнес вручную выбирает исполнителя.

## Запуск полной версии

Нужен Python 3.9+ и современный браузер. Для приложения не нужны npm, pip или сторонние Python-библиотеки.

В корне репозитория выполните:

```bash
python3 server/main.py --port 4174
```

Откройте [http://localhost:4174](http://localhost:4174). В шапке должно быть **«API подключён»**. Один сервер раздаёт сайт и API; задачи и отклики сохраняются в SQLite. При первом запуске автоматически создаются синтетические задачи, команды и отклики.

По умолчанию база находится в `server/data/sanamatch.sqlite3`. Путь можно изменить переменной `SANAMATCH_DB_PATH`. База, ключи и `.env` исключены из Git. Перезапуск сервера не сбрасывает данные. Кнопка **«Новая задача»** очищает только текущий черновик, сохраняя опубликованные задачи и отклики.

Сервер по умолчанию доступен только на этом компьютере. Это локальный MVP без авторизации, не готовый к открытому публичному размещению.

## Что работает

- Диалог с помощником и одновременно доступная редактируемая карточка; на телефоне — вкладки «Диалог» / «Карточка».
- Факты из диалога с цитатой-основанием и отдельно предложения помощника. Каждое изменение нужно применить или отклонить вручную.
- Защита ручных правок от устаревших AI-ответов, отмена последнего применения, повтор запроса при ошибке.
- Рейтинг 0–100 с расшифровкой и списком незаполненных критериев.
- Публикация с подтверждением, каталог с фильтрами и полная карточка «Подробнее».
- Отклик команды: идея, план, ссылка на прототип. Повторный отклик той же команды на ту же задачу запрещён.
- Ручной выбор одной, нескольких или ни одной команды; каждый отклик можно выбрать или отклонить.
- 100 progress points только за выполненный этап, отдельно подтверждённый бизнесом с описанием результата. Сам выбор команды баллов не даёт; повторное подтверждение не увеличивает баллы.
- Серверная валидация, сохранение в SQLite, ограничения размера запросов и структурированные сообщения об ошибках.

## AI: два честно обозначенных режима

`ai/service.py` содержит серверный диалоговый модуль и адаптер внешней модели. Модуль сам не меняет карточку, рейтинг, публикацию или решения бизнеса.

Раздел 5 официального кейса допускает локальную заглушку при недоступности внешнего API, если показаны промпт, формат входа/выхода и обработка некорректного ответа. Эти материалы есть в `ai/service.py`, `ai/test_service.py` и `docs/ai-handoff.md`. Для воспроизводимой демонстрации API-ключ не обязателен; локальный режим не выдаётся за ответ LLM.

- **Без настройки провайдера:** работает локальный помощник на правилах (`mode: "fallback"`), без внешних запросов и оплаты. Он извлекает простые факты, различает артефакт и критерий успеха и задаёт следующий вопрос. Это не LLM.
- **С настроенным провайдером:** модуль пробует внешний API. Реализован адаптер `openai` через Responses API. Ключ хранится только на сервере. Ошибка, таймаут или невалидный ответ переключают модуль на локальный fallback.

Параметры перечислены в `.env.example`: `AI_PROVIDER`, `AI_API_KEY`, `AI_MODEL`, `AI_BASE_URL`, `AI_TIMEOUT_SECONDS`. Собственные значения можно задать в окружении или в локальном `.env`, после чего перезапустить сервер. Не публикуйте ключи и не отправляйте их в чат. Для работы без LLM все эти параметры можно оставить пустыми.

Метка **«API подключён»** означает только доступность бэкенда. Метка **«AI подключён»** появляется лишь после ответа с `mode: "llm"`; `aiConfigured` в health означает наличие настроек, а не проверенную доступность модели. Проверки в репозитории не расходуют API-кредиты. Живой вызов внешней модели в интеграционной проверке не выполнялся.

Рабочий prompt и схема ответа находятся в `ai/service.py`. Текст пользователя считается данными, а не системными инструкциями. Извлечённые факты проверяются на наличие точной цитаты; это не доказывает истинность исходных сведений.

### Контракт диалога

`POST /api/ai/chat` принимает:

```json
{
  "requestId": "ui-example-1",
  "cardVersion": 0,
  "draft": "Нужно быстрее распределять обращения клиентов.",
  "card": {"result": "", "success": ""},
  "messages": [{"role": "user", "content": "Нужен прототип классификатора."}],
  "language": "ru"
}
```

Ответ содержит `requestId`, `cardVersion`, `mode`, `reply`, `updates`, `suggestions`, `missingFields`, `issues`. В `updates` каждый элемент имеет `field`, `value`, `evidence`; в `suggestions` — `field`, `value`, `reason`. Интерфейс проверяет версию и ждёт подтверждения пользователя перед изменением карточки.

Ограничения: черновик до 5000 символов, сообщение до 4000; в API передаются последние 20 сообщений в пределах 24 000 символов и текущая карточка. Старые сообщения остаются видны до перезагрузки, но могут не входить в контекст модели. Поля карточки для AI — до 1200 символов. Поддерживается русский язык.

## Формула рейтинга

| Критерий | Баллы |
| --- | ---: |
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт **и** формат взаимодействия | 10 |

0–39 — черновик; 40–69 — рабочая; 70–89 — готовая; 90–100 — приоритетная. Баллы отражают заполненность, не качество или истинность текста. Сервер вычисляет рейтинг самостоятельно. Для публикации обязательны название, контекст и ожидаемый результат; минимального порога рейтинга нет.

## Архитектура

```text
index.html + CSS           интерфейс, мобильные вкладки и диалоги
app.js                    карточка, диалог, подтверждения, каталог, отклики
ui/api-client.js          HTTP API и сообщения об ошибках
ui/demo-adapter.js        изолированный статический демо-режим
server/main.py            HTTP, SQLite, валидация, прокси к AI-модулю
ai/service.py             обработка диалога, LLM-адаптер и локальный fallback
```

Задачи: `GET/POST /api/tasks`, `GET/PATCH /api/tasks/:id`. Команды: `GET /api/teams`. Отклики: `GET/POST /api/responses`, `PATCH /api/responses/:id`. Ошибки имеют вид `{"error":{"code":"…","message":"…"}}`.

Для ручного выбора отправляется `{"status":"selected"}`, для отклонения — `{"status":"rejected"}`. Подтверждение выполненного этапа: `{"progressConfirmed":true,"progressNote":"Что проверил бизнес"}`. Оно доступно только выбранной команде, требует непустого описания и начисляет баллы один раз. Решения и подтверждения сохраняются в SQLite. Обновление старой базы сохраняет записи и решения, снимает прежнее ограничение одной команды и не считает старый выбор выполненным этапом.

## Проверки

```bash
python3 -m unittest discover -s ai -p 'test_*.py' -v
python3 -m unittest discover -s server/tests -p 'test_*.py' -v
```

Для дополнительных тестов UI нужен Node.js 20+:

```bash
node --test ui/tests/integration.test.cjs
node --check app.js
```

Python-тесты используют временные базы, локальные порты и подставные ответы модели. UI-тесты проверяют клиентский контракт и переходы состояния в изолированном окружении; они не заменяют реальный браузерный прогон. Сценарий ручной проверки — в [DEMO.md](DEMO.md).

## Статический запасной вариант

```bash
python3 -m http.server 4173 --bind 127.0.0.1
```

На [http://localhost:4173](http://localhost:4173) без API интерфейс покажет **«Локальный демо-режим»**: синтетические данные, фиксированные тестовые ответы, хранение только в `localStorage` этого браузера. Это не полная серверная версия и не подключённая модель. Кнопка сброса восстанавливает только эти демо-данные. Они не переносятся в SQLite автоматически.

## Ограничения MVP

- Нет учётных записей, проверки полномочий бизнеса/команд и готовности к публичному хостингу.
- Чат, неподтверждённые предложения и неопубликованный черновик находятся в памяти страницы и пропадут после перезагрузки; опубликованные задачи и отклики сохраняются в SQLite.
- Другой открытый браузер увидит изменения после обновления страницы; live-синхронизации нет.
- Локальный fallback понимает ограниченный набор формулировок. Ошибки интерпретации возможны; финальные сведения проверяет бизнес.
- Все начальные данные синтетические. Демонстрационные ссылки не являются реально разработанными прототипами.
- NVIDIA-адаптер, обучение ML-модели, уведомления и загрузка файлов не реализованы.
